# Debt Simplification Algorithm

When multiple people share expenses on a trip, pairwise debts quickly form cycles and redundant payments. For example, if Alice owes Bob 20 EUR, Bob owes Charlie 20 EUR, and Charlie owes Alice 20 EUR, no actual money needs to change hands.

TabMate reduces arbitrary debt networks to the minimal number of direct payments using the minimum cash flow algorithm.

## Mathematical Formulation

### 1. Net Balance Calculation
For each member `u` in a group:

```
Net(u) = Total_Paid(u) - Total_Allocated(u) + Received_Settlements(u) - Paid_Settlements(u)
```

Where:
- `Total_Paid(u)` is the sum of expenses paid by member `u`.
- `Total_Allocated(u)` is the sum of split amounts assigned to member `u`.
- `Received_Settlements(u)` is the sum of previous settlements paid to `u`.
- `Paid_Settlements(u)` is the sum of previous settlements paid by `u`.

Because every expense amount paid by one person is assigned to one or more members, the sum of all net balances across the group equals zero:

```
Σ Net(u) = 0
```

### 2. Debtor and Creditor Partitioning
The algorithm partitions the members into two disjoint sets:
- **Debtors ($D$):** Members with `Net(u) < -0.01` (people who owe money).
- **Creditors ($C$):** Members with `Net(u) > 0.01` (people who are owed money).

Members whose net balance is between -0.01 and 0.01 are considered settled and excluded from further steps.

### 3. Greedy Elimination Loop
1. Sort $D$ descending by absolute debt amount.
2. Sort $C$ descending by credit amount.
3. Take the largest debtor $d$ and the largest creditor $c$.
4. Calculate the settlement amount:
   ```
   amount = min(|Net(d)|, Net(c))
   ```
5. Emit a transaction: `$d` pays `$c` the value `amount`.
6. Update the balances:
   ```
   Net(d) = Net(d) + amount
   Net(c) = Net(c) - amount
   ```
7. Whichever member's balance reaches zero is removed from the active set. If both reach zero simultaneously, both are removed.
8. Repeat until both $D$ and $C$ are empty.

## Upper Bound on Transactions

In a group of $N$ members, the maximum number of transactions generated by this algorithm is $N - 1$. In practice, when some sub-groups balance internally, the number of transactions is even lower.

By contrast, without debt simplification, $N$ members could produce up to $N(N - 1) / 2$ pairwise payments.

## Precision and Rounding

JavaScript uses IEEE 754 double-precision floating-point numbers, which can produce rounding artifacts such as `0.1 + 0.2 = 0.30000000000000004`.

TabMate guards against fractional penny errors by:
1. Normalizing each subtraction with `Math.round(val * 100) / 100`.
2. Treating any balance whose absolute value is under `0.01` EUR as settled.
3. During equal splits, distributing any non-divisible remainder (e.g. 100 EUR among 3 people = 33.33, 33.33, 33.34) to the final split item.
